Deploying blog.sanvasify.com to Cloudflare Pages

Deploying websites in 2026 has never been simpler, more performant, or more cost-effective. Today, we are walking through the architectural setup of blog.sanvasify.com hosted entirely on Cloudflare Pages.

Why Cloudflare Pages?

For a content-focused website like a blog, static HTML combined with modern CSS provides the ultimate developer and user experience. Cloudflare Pages offers:

  • Global Edge Network: Your blog is cached and delivered from edge servers closer to your users, guaranteeing sub-second load times.
  • Zero Cost Tier: Perfect for personal portfolios and independent writing.
  • Git Integration: Pushing changes to the main branch automatically triggers preview builds and production deployments.
"Simplicity is the ultimate sophistication. When you don't have to manage servers or complex build configurations, you can focus purely on creating content."

The Build Configuration Gotcha

During deployment, we encountered a classic directory nesting issue: Error: Output directory "blog/blog" not found. This occurs when Cloudflare resolves the output directory relative to the configured root folder.

To avoid this, we simplified our configuration to keep the repository root / as the build environment root, and pointed the Build output directory directly to blog. This structure keeps our Go application backend decoupled from the static blog content beautifully.
